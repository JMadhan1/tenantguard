How it works

The self-healing remediation loop

The agent proposes a fix. If the fix breaks something, the verifier catches it, the agent reverts, and tries again. Tests decide — not the AI.

Integration

      
CI/CD — GitHub Action

      
Drop this into any repo. On every PR: scan, fix, verify, comment. The same self-correcting loop in your pipeline.

      

        

          .github/workflows/tenantguard.yml
        

        
name: TenantGuard Security Audit
on: [pull_request]
jobs:
  security-check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: JMadhan1/tenantguard-action@v1
        with:
          scan-dir: ./src
          auto-fix: true
          verify: true        # tests must pass
          model: claude-opus-4.6

Safety

      
Is this safe?

      

        
Never runs your code. Only built-in synthetic fixtures. Never a visitor's repo.

        
Can't break anything. Edits a throwaway copy. Never commits, pushes, or merges.

        
Tests decide. A fix only counts if ALL security AND ALL functionality tests pass.

        
Bounded. Rate-limited, daily-capped, all data synthetic, no secrets.
