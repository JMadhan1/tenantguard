An AI agent that fixes security bugs — and catches its own mistakes.

One of the most common security flaws lets one customer read another customer's data (a “tenant-isolation” / IDOR bug). Fixing it is risky: a careless patch can block the leak but also break legitimate access. TenantGuard fixes it and proves it didn't break anything — by running the tests itself, not by trusting the AI.

How it works — in 3 steps

1

The setup

A sample invoicing app has a planted bug: any logged-in user can read any tenant's invoices — a cross-tenant leak.

2

The agent runs

TenantGuard reproduces the leak, writes a fix, and re-runs the tests. If its fix breaks legitimate access, it undoes it and tries again.

3

The proof

“Fixed” means both: cross-tenant access is blocked and legitimate access still works — decided by tests, not the AI.

Is this safe?

  

    
    
      
  • It never runs your code. The demo only fixes a built-in synthetic sample app — never a visitor's repo (executing untrusted code is exactly what a security tool must not do).
    • 
      
  • It can't break anything. The agent edits a throwaway copy, never commits, pushes, or merges, and never runs AI-generated shell commands.
    • 
      
  • Tests decide, not the AI. A fix only counts if cross-tenant access is blocked and legitimate access still passes.
    • 
      
  • Bounded. Rate-limited with a daily cap; all data is synthetic; no secrets.
